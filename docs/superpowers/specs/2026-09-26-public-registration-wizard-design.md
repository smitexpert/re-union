# Public Registration Wizard — Design Spec

**Date:** 2026-09-26
**Status:** Approved
**Scope:** Replace the placeholder `REGISTER_URL` on the landing page with an in-app, multi-step registration wizard and a standalone payment page.

## Goal

The landing page's "Register Now" button currently links to `https://example.com/register`. We are replacing that with an in-app experience:

- A multi-step wizard that captures a `Student`, picks the open `Reunion`, collects guests, and confirms.
- A standalone payment page reachable from the post-submit success screen, gated on `payment_status === 'unpaid'`.
- A Bangla "no available event" state when no active reunion is currently open for registration.

## Decisions (locked in)

| Decision | Choice |
|---|---|
| Auth model | None — collect everything in the wizard |
| Wizard render | Single Inertia page, client-side state |
| Payment flow | Separate `/payments/{code}` page, opened by a "Make Payment" button on success |
| Closed state | Inline Bangla message on `/register` |
| Step persistence | None — atomic single POST at the end |
| Fee calculation | Server-recomputed, never trusted from the client |
| Tests | Skipped unless explicitly requested |
| Visual style | Modern, mobile-first |

## Architecture

### Routes

| Method | URL | Action |
|---|---|---|
| GET | `/register` | `RegistrationController@show` |
| POST | `/register` | `RegistrationController@store` |
| GET | `/payments/{registration}` | `PaymentController@show` |
| POST | `/payments/{registration}` | `PaymentController@store` |

### Backend

**`app/Models/Reunion.php`** — add `currentOpenForRegistration(): ?self`. Single source of truth for "is there a registerable event?". Returns the first `Reunion` where `is_active = true` AND `event_date >= today` AND (`registration_deadline IS NULL` OR `registration_deadline >= today`), ordered by `event_date asc`. Returns `null` if none.

**`app/Models/ReunionRegistration.php`** — add `createFor(Reunion $reunion, Student $student, array $data, array $guests): self`. Wraps: setting `total_fee` from the calculator, attaching `ReunionGuest` rows, firing model events. The `registration_code` is auto-generated by the existing `booted()` hook.

**`app/Services/RegistrationFeeCalculator.php`** — `total(Reunion $reunion, int $adultCount, int $childCount): string` (decimal string). Reads active `ReunionGuestFee` rows for the given `guest_type` to look up per-head fees. `registration_fee` from the reunion is always added once. Used by both `RegistrationController@store` (server-recompute) and `RegistrationController@show` (live preview payload).

**`app/Http/Controllers/RegistrationController.php`** — `show` resolves `Reunion::currentOpenForRegistration()`; if null, returns Inertia page with `{ mode: 'closed' }`; otherwise returns `{ mode: 'open', reunion, feeBreakdown }`. `store` uses `StoreRegistrationRequest` to validate, then creates the `Student`, calls `ReunionRegistration::createFor()`, and redirects to `/register/success` (a separate Inertia render that reads the registration by code from session).

Actually, simplest: `store` redirects to `/payments/{code}` only when `payment_status === 'unpaid'`, otherwise to `/register/success/{code}`. The success page is rendered by a `RegistrationController@success` action. `payment_status` defaults to `unpaid`, so the common path is to land on `/payments/{code}`.

**`app/Http/Requests/StoreRegistrationRequest.php`** — validates:
- `student.full_name` required, max 150
- `student.email` required, email, max 150, unique in `students` table
- `student.phone` required, max 20, unique in `students` table
- `student.graduation_year` required, integer, between 1950 and 2100
- `student.department` required, max 100
- `student.session`, `student.current_occupation`, `student.present_address`, `student.permanent_address`, `student.office_address` — optional, with max lengths matching model
- `tshirt_size` optional, max 10
- `guest_count_adult` required, integer, min 0
- `guest_count_child` required, integer, min 0
- `registration_status` required, in: `pending,confirmed,cancelled`, default `pending`
- `notes` optional

**`app/Http/Controllers/PaymentController.php`** — `show($registration)` 404s if the code is unknown; renders `Payment.jsx` with the registration + reunion summary + current `payment_status`. Refuses to render the form if a `completed` `Payment` already exists — shows a "payment already recorded" card instead. `store` validates and creates a `Payment` row with `status='pending'`, does NOT mutate `registration.payment_status` (manual reconciliation), then redirects back to `/payments/{code}` with a success flash.

**`app/Http/Requests/StorePaymentRequest.php`** — validates:
- `payment_method` required, in: `bkash,nagad,bank_transfer,cash,card`
- `amount` required, numeric, min 1
- `transaction_id` optional, max 100
- `send_from_mobile_number` optional, max 20
- `notes` optional

### Frontend

**`resources/js/pages/Register.jsx`** — top-level. Reads `mode` from props. Renders `ClosedNotice` (Bangla) if closed, otherwise `Wizard` (open).

**`resources/js/pages/Payment.jsx`** — top-level payment page.

**`resources/js/components/registration/Wizard.jsx`** — owns all 4-step state, runs a single `router.post('/register', payload, { onSuccess, onError })` on final submit. On success, Inertia navigates to `/payments/{code}` (the controller redirect).

**`resources/js/components/registration/Stepper.jsx`** — thin progress bar with `Step X of 4` label and `role="progressbar"`.

**`resources/js/components/registration/Step1Student.jsx`** — student fields, matches Student model `$fillable`. Uses `inputMode`, `autoComplete` per mobile-best-practice.

**`resources/js/components/registration/Step2Reunion.jsx`** — read-only summary of the chosen reunion + live fee preview using `feeBreakdown` from server.

**`resources/js/components/registration/Step3Guests.jsx`** — adult count + child count + tshirt size; live total updates as counts change.

**`resources/js/components/registration/Step4Review.jsx`** — read-only summary + `registration_status` radio (default `pending`) + `notes` textarea + submit button.

**`resources/js/components/registration/ClosedNotice.jsx`** — Bangla "দুঃখিত, বর্তমানে কোনো রেজিস্ট্রেশন চলছে না" card. Includes a deep-link to `/payments/{code}` for users who already have a registration code.

### Landing-page wiring

**`resources/js/pages/Home.jsx`** — drop the `REGISTER_URL` constant. Pass `registerUrl="/register"` instead.

**`resources/js/components/landing/Header.jsx`, `Hero.jsx`, `StickyCta.jsx`** — change `<a href target="_blank">` to `<Link href>`. Stop importing external registration URL.

## Data flow

### Open-reunion path

1. User clicks Register → Inertia visits `/register`.
2. Controller resolves `Reunion::currentOpenForRegistration()`.
3. Returns Inertia render with `{ mode: 'open', reunion, feeBreakdown }`.
4. `Wizard` mounts with all 4 steps; student/guests data lives in `useState`.
5. On final submit: `router.post('/register', { student: {...}, guests: { adult, child }, tshirt_size, registration_status, notes })`.
6. `StoreRegistrationRequest` validates. On fail: 422 → wizard re-mounts at step 4 with field errors.
7. On success: `RegistrationController@store` creates Student → Registration → Guests atomically, recomputes `total_fee`, sets `payment_status='unpaid'`, sets `registration_status` from input.
8. Redirect to `/payments/{code}`.

### Closed path

1. User clicks Register → `/register`.
2. Controller finds no open reunion → returns `{ mode: 'closed', banglaMessage }`.
3. `ClosedNotice` renders the Bangla apology card with a deep-link to `/payments/{code}`.

### Payment path

1. From `/payments/{code}` (entered directly or via success screen).
2. `PaymentController@show` looks up by `registration_code`, 404 if missing.
3. If registration has a `completed` payment: shows "already paid" card, no form.
4. Otherwise: registration summary + payment form.
5. `POST /payments/{code}` validates + creates `Payment(status='pending')`.
6. Redirect back to `/payments/{code}` with success flash "payment submitted, pending review".

## Error handling

| Failure | Behavior |
|---|---|
| No active reunion | Closed Bangla notice |
| Validation failure | 422, errors render under fields |
| Duplicate email/phone | 422, field error |
| Reunion deleted mid-flight | `try/catch ModelNotFoundException` → redirect back with flash |
| Duplicate `registration_code` | Loop inside `generateRegistrationCode()` |
| Unknown payment code | 404 |
| Already-paid registration | Skip form, show "already paid" card |
| Invalid payment input | 422 |

## Visual direction

Mobile-first, modern, brand-consistent:

- Card pattern: `rounded-2xl border border-gray-100 bg-white shadow-sm`
- Inputs: `rounded-xl`, focus ring `ring-brand-ink/30`
- Primary CTA: `bg-linear-to-r from-brand to-brand-ink` (matches landing)
- Stepper: thin progress bar + "Step X of 4", labels hidden on mobile, dots only
- Sticky bottom CTA bar on mobile (back/continue)
- `prefers-reduced-motion` respected via `motion-safe:` prefix
- Inputs use `inputMode`, `autoComplete`, `type` per mobile best practice
- `min-h-12` tap targets, `text-base` to prevent iOS zoom
- Bangla copy: "দুঃখিত, বর্তমানে কোনো রেজিস্ট্রেশন চলছে না..."
